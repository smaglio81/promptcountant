I would like to create a VSCode extension that will make AI chat session information easier for the user to review and understand the models, tokens, and costs of the sessions.

A lot of AI coding agents, have a folder on disk where they save information about prompt history, about what they have sent to the LLM and what they received back. They also contain vector databases to help semantic search locally. Within GitHub Copilot, the location is usually here on a Windows machine. I wonder if there are potentially the same folders set up for Claude and for Cursor and for Pi.

What I'd like to do is look through those directories for the different chat sessions and then aggregate the data within those chat sessions to focus on the amount of tokens that are used in each one of those sessions and how much the expected cost for those tokens would be. I'd also like to find out the duration of the chat sessions and the number of requests it takes to work with the LLMs.

When it comes to GitHub Copilot, I know under each one of these chat session folders there is a main.jsonl file. That file has a list of entries for each time the user prompted the machine and each time the agent communicated with the LLM. There is a particular signifier for entries where the agent was communicating with the LLM. I'd like to focus on those entries. Those entries contain information about the duration of how long the agent spent talking to the LLM. They also contain the number of tokens and the model. I'd like to pull information from really those entries, and then, if there is an API available that you can go and look up the cost of LLMs by millions of tokens, I'd like to be able to call out to that API and figure out the cost estimation for using the LLM.

I would like for this to be an extension within VS Code, and I would like for that extension to be able to show the different chat agents that are supported. The first agent we should support is GitHub Copilot. I would like for it to list the sessions, if possible. I would like for it to list and group those sessions by the workspace that they are associated with. I would like to be able to search inside of the sessions for keywords, so I would like a search feature on the extensions display area. Ideally, the search feature would be something where there is an input box that you can type into, and when you type into the box it will filter the sessions by the matching sessions.

I would like to be able to double click on a session and have it pull up and show the full JSONL list of items. It should not show the entirety of the JSONL file. That file is very large. It should show a list on screen of each of the items inside of the JSONL list. It should talk about highlighting the lines that have to do with talking to the LLM, the tokens, and the amount of time. Each of the entries should give an idea to the end user where they were within the conversation of that chat session.

I would like there to be an interface created which will allow you to aggregate data across multiple sessions so that the roll-up of the amount of token usage and the cost across an entire workspace can be seen. I would like the data aggregation to be stored locally on disk inside of a SQLite database. As data is aggregated, it gets saved into the SQLite database for quick lookup. You're going to need to figure out how to create referential keys between the sessions and the SQLite database tables.

Upon first load of the extension, it should discover the different session information that is already stored on the machine. It should display to the end user that it is going to start aggregating data from those sessions in the background on a background thread and that it will make the sessions available as it completes analysis. These sessions should not consume too much of the CPU or memory. I would like, if there's a way to possibly constrain them so that they can't use more than 15% CPU and they need to run in the background without holding on to any set of UI threads. That's going to be really important to make sure that the end user isn't affected by the analysis.
